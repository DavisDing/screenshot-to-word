# Screenshot To Word

面向测试执行场景的桌面工具。它从 Excel 读取待执行的测试用例，按用例或步骤进行全屏截图与标注，随后自动将截图写入 Word 报告，并回写 Excel 的执行状态。

## 功能概览

- 支持 `.xlsx` 与 `.xlsm` 格式的 Excel 用例文件；回写 `.xlsm` 执行状态时保留已有 VBA 宏。
- 自动识别表头；无法准确识别时，可在界面中查看列样例并手动确认列含义。
- 支持基础用例和步骤式用例；步骤式用例会逐条展示和执行。
- 按工作簿标签顺序依次执行所有非空工作表（含隐藏表），逐表确认列映射；空白或仅有格式的表自动跳过。
- 支持读取测试名称、验证点、步骤名称、步骤描述、预期结果和测试结果等字段。
- 支持合并单元格中的测试名称和验证点，并正确继承到对应步骤。
- 自动跳过已执行的记录（支持“已执行 / 通过 / 完成 / 成功 / passed / done”等状态）。
- 通过悬浮执行面板逐项处理，按 `F8` 可快速截图。
- 截图标注支持方形、圆形、荧光笔、画笔、文字、裁剪、缩放与撤销。
- 标注保存后，自动追加到以测试名称命名的 Word 报告；相同验证点不会重复写入。
- 自动把已完成项的测试结果回写为“已执行”。
- 带有图片的 Excel 可连续回写；每次写入同目录临时副本后再替换，保存失败时保留原文件。
- 提供运行日志、崩溃日志及输入/输出目录快捷入口。

## 运行环境

- Python 3.12（当前构建验证版本）
- Windows 或 macOS

主要依赖：PySide6、openpyxl、python-docx、Pillow 和 PyInstaller。完整版本要求见 [requirements.txt](/Volumes/DingHao_UP/screenshot-to-word/requirements.txt)。

> macOS 首次使用截图功能时，可能需要在“系统设置 → 隐私与安全性 → 屏幕录制”中允许该应用截图。

## 安装与启动

在项目目录执行：

```bash
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python main.py
```

程序启动后会自动创建以下目录（如尚不存在）：

```text
excel_input/   # 建议存放待执行 Excel
word_output/   # 自动生成的 Word 报告
Temp/          # 截图临时文件
logs/          # 运行日志和启动异常日志
```

也可以在启动后从文件选择器中选取任意位置的 Excel 文件。

## 使用流程

1. 在主界面点击“选择 Excel”。
2. 按工作表顺序，在各自的“确认 Excel 列含义”窗口核对自动识别结果，必要时手动选择每个字段对应的列；标题旁会显示当前工作表。取消任意一张表的映射会取消整次加载。
3. 确认后会出现置顶的悬浮执行面板，显示当前用例、验证点及步骤信息。
4. 点击“截图并标注”或按 `F8`。主窗口和执行面板会暂时隐藏，避免出现在截图中。
5. 在标注窗口完成标记后点击“保存”（快捷键 `Ctrl+S`）。
6. 程序自动将截图写入 Word，并将当前 Excel 行的测试结果改为“已执行”；然后点击“下一条”继续。
7. 全部处理完成后，主窗口会恢复，可从“打开输出目录”查看报告。

在标注窗口中，`Ctrl+Z` 用于撤销，`Esc` 用于取消本次标注。

### 关于“跳过”与“结束”

- “跳过”仅在本次执行中跳到下一项，**不会**写入 Word，也**不会**修改 Excel 状态。
- “结束”会退出当前执行流程并返回主窗口；已保存的项目仍保留其已写入的 Word 内容和 Excel 状态。

## Excel 字段说明

以下三列为必填项：

| 字段 | 作用 | 常见别名 |
| --- | --- | --- |
| 测试名称 | Word 报告名称及用例标题 | 用例名称、测试用例、Case Name、Test Name |
| 验证点 | 报告中的验证项 | 检查点、校验点、Checkpoint |
| 测试结果 | 用于识别和回写执行状态 | 结果、状态、执行结果、Result、Status |

以下列为可选项；任意一列存在时，程序会按步骤式用例处理：

| 字段 | 作用 |
| --- | --- |
| 步骤名称 | 当前步骤的标题或编号 |
| 步骤描述 | 当前步骤的操作说明 |
| 预期结果 | 当前步骤的预期表现 |

表头不必固定在第 1 行，程序会在前 15 行中自动寻找最可能的表头行。若列名不规范，请在映射窗口中手动选择；窗口会显示前三个非空样例值供核对。

## 输入示例

基础用例：

| 测试名称 | 验证点 | 测试结果 |
| --- | --- | --- |
| 登录功能 | 登录成功 | |

步骤式用例：

| 测试名称 | 验证点 | 步骤名称 | 步骤描述 | 预期结果 | 测试结果 |
| --- | --- | --- | --- | --- | --- |
| 登录功能 | 登录成功 | 1 | 打开登录页 | 显示登录表单 | |
| 登录功能 | 登录成功 | 2 | 输入正确账号密码 | 进入首页 | |

步骤式表格中，测试名称和验证点可使用纵向合并单元格。每个待执行步骤在保存截图后都会独立回写自己的“测试结果”单元格。

多工作表会按标签顺序合并为一条执行队列，执行面板标题显示当前工作表。各表的列顺序、表头位置和基础/步骤模式可不同；名称和验证点只在各自工作表内继承。回写使用“工作表名称 + 原始行号”，避免不同表的相同行号互相覆盖。包含内容但不符合用例结构的工作表也需要确认必要列映射，不会静默丢弃。

状态保存直接修改目标工作表 XML，不再每步调用 openpyxl 重新加载和保存整本工作簿。宏、图片和其他 ZIP 部件的解压内容保持不变；仍需流式复制、压缩整个 ZIP 到同目录临时文件，再替换原文件，不能视为常数时间的单元格写入。保存期间检测到其他程序修改文件时会中止，并保留对方保存的版本；执行期间仍应避免增删行列或调整表结构。

没有测试名称、验证点或步骤内容的空行会自动跳过，包括带格式的表尾空行；有步骤内容的行仍可继承测试名称和验证点。

## Word 输出规则

- 每个测试名称生成或追加一个 `.docx` 文件。
- 文件名中的 Windows 不支持字符会自动替换为下划线。
- 不同测试名称在字符替换或长度截断后撞名时，会添加摘要后缀，分别保存报告。追加已有报告前会核对用例身份；同一测试名称再次执行时仍追加自己的报告。
- 已有报告保留原位置和内容；此前已经混入同一报告的内容需要人工核对，程序不会自动拆分。
- 新报告会以测试名称作为一级标题。
- 每个验证点只写入一次；随后步骤会继续追加步骤信息和截图。
- 截图宽度固定为约 5.8 英寸，以适配常见报告页面。

```bash
python -m compileall -q main.py qt_app tests scripts pyinstaller_hooks
python tests/smoke_test_services.py
python -m unittest discover -s tests -p 'test_*.py' -v
```

冒烟测试覆盖 Excel 列映射、执行状态回写、合并单元格步骤读取，以及 Word 验证点去重。

回归测试覆盖多工作表顺序、独立列映射与状态回写、`.xlsm` 宏包保留、跨工作表图片在连续回写时保留、写入/替换失败时保护原文件并允许重试、空行过滤与有效步骤继承、报告文件名碰撞及跨次追加。Qt 无屏幕测试使用真实 Excel/Word 服务验证逐表映射、跨表保存、取消、跳过与结束；它不能替代原生截图、系统权限和平台验收。宏包保留测试不会执行 VBA 宏。

## 本地打包与体积控制

两端共用 `DesktopTestTool.spec`，通过 PyInstaller 官方 hooks 按需收集依赖，排除当前业务未使用的 WebEngine、QML/Quick、3D 和多媒体模块。保留完整 PySide6 安装依赖，不切换 Essentials，也不在成品目录中批量删除动态库。Pillow、Qt 平台插件、SVG、shiboken6、运行时辅助模块及 Word 默认模板必须保留。

`pyinstaller_hooks/hook-PySide6.QtGui.py` 复用官方 QtGui 收集逻辑，只在依赖扫描前排除未使用的 Qt 虚拟键盘插件，避免它重新带入 QML/Quick。系统原生输入法相关组件和图像插件继续保留。

Windows：

```powershell
python -m PyInstaller --noconfirm --clean DesktopTestTool.spec
python scripts/check_bundle.py dist/DesktopTestTool
```

macOS：

```bash
python scripts/make_icns.py icon.ico icon.icns
python -m PyInstaller --noconfirm --clean DesktopTestTool.spec
python scripts/check_bundle.py dist/DesktopTestTool.app
```

成品检查会读取实际打包的 Python 模块索引和文件列表：缺少延迟加载服务、Pillow、运行时辅助模块、必要 Qt 扩展/插件或文档资源，以及重新带入上述大型 Qt 模块时均报错。它不启动 GUI，不能替代两端原生验收。

发布前仍需验证：启动和文件选择、SVG 箭头、中文文字、截图权限与 F8、标注/PNG 保存、Word 新建与追加，以及 `.xlsx`/`.xlsm` 回写时保留宏和已有图片。包大小应以对应提交的实际产物为准。

## CI 与发布

- 分支推送、Pull Request 和手动运行会执行语法检查、服务冒烟及回归测试，并构建 Windows 和 macOS 包，上传到该次 Actions 的 artifacts。
- 发布入口有两种：推送 `v0.0.37` 这样的版本标签；或在 Actions → Build Desktop Apps and Release → Run workflow 选择默认分支，并填写 `release_tag`（例如 `v0.0.37`）。手动输入留空时只构建 artifacts。版本号支持 `v1.0.0-rc.1` 形式的预发布后缀。
- Release 等待两端测试、构建及 artifact 上传均成功后，再附带两份安装包发布。手动发布会在构建的精确提交上创建指定标签；若同名标签指向其他提交则失败，避免把不同提交的包挂到同一版本。请为新版本使用未发布过的版本号。
- 正式构建的应用版本与 Release 标签一致，其他构建使用 `dev-<提交短 SHA>`。工作流不会为普通分支推送自动生成版本号。
- 构建后先执行成品模块与资源检查，通过后才压缩、上传 artifact；检查失败会阻止发布。
